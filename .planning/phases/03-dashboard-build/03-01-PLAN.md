<task type="auto">
  <name>Task 1: Convex schema multi-tenant + auth config + queries/mutations</name>
  <files>convex/auth.config.ts, convex/schema.ts, convex/leads.ts, convex/stats.ts, convex/users.ts</files>
  <action>
1. Create `convex/auth.config.ts` — Clerk JWT validation:
   ```typescript
   export default {
     providers: [{
       domain: process.env.CLERK_JWT_ISSUER_DOMAIN,
       applicationID: "convex",
     }],
   };
   ```

2. Update `convex/schema.ts` — add orgId + estados + auditTrail to leads table. Keep ALL existing fields from the SAAN v1.0 schema (empresa, contacto, email, linkedin, industria, score, scoreCategory, etc). Add new fields:
   - `orgId: v.string()` (Clerk Organization ID)
   - `estado: v.union(v.literal("sin_asignar"), v.literal("asignado"), v.literal("en_progreso"), v.literal("cerrado"))`
   - `subestado: v.optional(v.union(v.literal("ganado"), v.literal("perdido"), v.literal("descartado")))`
   - `asignadoA: v.optional(v.string())` (Clerk userId del SDR)
   - `auditTrail: v.optional(v.array(v.object({accion: v.string(), usuarioId: v.string(), usuarioNombre: v.string(), timestamp: v.number()})))`
   Add indexes: `by_orgId`, `by_orgId_estado`, `by_orgId_asignadoA`, `by_orgId_score`.
   NOTE: If convex/ directory does not exist, run `npx convex init` first. If schema already exists from SAAN, extend it (do not delete existing fields).

3. Create `convex/leads.ts` — multi-tenant queries and mutations:
   - `getLeadsByOrg` — query all leads for org, ordered desc, max 200. Uses `withIndex("by_orgId")`. Extracts orgId from `ctx.auth.getUserIdentity()` claim `org_id`.
   - `getLeadsByStatus(status)` — query leads by org+status using `by_orgId_estado` index.
   - `getLeadById(leadId)` — get single lead, verify orgId matches.
   - `updateLeadStatus(leadId, nuevoEstado, subestado?)` — patch lead, verify org ownership, append to auditTrail.
   - `assignLead(leadId, sdrUserId, sdrNombre)` — set asignadoA, change estado to "asignado", append to auditTrail.
   - `bulkAssignLeads(leadIds[], sdrUserId, sdrNombre)` — assign multiple leads to one SDR.
   - `reasignarLead(leadId, nuevoSdrUserId, nuevoSdrNombre)` — reassign with confirmation audit entry.
   CRITICAL: Every query/mutation must call `ctx.auth.getUserIdentity()`, extract `org_id` from identity, and filter/verify by orgId. Never trust orgId from args.

4. Create `convex/stats.ts` — aggregation queries:
   - `getLeadsStats` — count leads by status (sin_asignar, asignado, en_progreso, cerrado), count by scoreCategory (HOT, WARM, NURTURE, SKIP), count nuevos (last 30 days), count cerrado+ganado for conversion rate. All filtered by orgId from JWT.
   - `getFunnelData` — aggregate lead counts per stage for funnel visualization.
   - `getLeadsByIndustry` — group leads by industria field, return counts.

5. Create `convex/users.ts` — user/role management:
   - `getOrCreateUser(clerkUserId, nombre, email, rol)` — upsert user record with orgId from JWT.
   - `getTeamMembers` — list all users for the org (for assignment dropdowns).
   - `getUserRole` — return the role of the current user.

Run `npx convex deploy` (or `npx convex dev --once`) to push schema and functions.

  <action>
1. Create `shared/auth.js` — Clerk JS bootstrap for vanilla JS:
   - `initAuth()` — waits for `Clerk.load()`, checks `Clerk.user`, redirects to `/app/login.html` if no session. Gets `orgId` from `Clerk.session.lastActiveOrganizationId`. If no orgId, shows "Selecciona una organizacion" screen. Stores orgId in `window.CURRENT_ORG_ID`.
   - `getConvexToken()` — calls `Clerk.session.getToken({ template: 'convex' })`. Call before EVERY Convex query (Clerk caches internally if not expired).
   - `getCurrentRole()` — determine user role. Strategy: check Convex `users` table for role field. Fallback: use Clerk org role metadata. Store in `window.CURRENT_ROLE`.
   - `redirectToRolePage()` — after auth, redirect to `/app/ceo.html`, `/app/vp-ventas.html`, or `/app/sdr.html` based on role.
   - Export all functions on `window.SistecoAuth`.

2. Create `shared/convex-client.js` — ConvexHttpClient wrapper:
   - Initialize `ConvexHttpClient` with `window.CONVEX_URL` (set in HTML or env).
   - `queryConvex(queryFn, args)` — refreshes token via `getConvexToken()`, calls `setAuth(token)`, then `convex.query(queryFn, args)`. Catches auth errors and redirects to login. Per DASH-07: one-shot queries, NO reactive subscriptions.
   - `mutateConvex(mutationFn, args)` — same token refresh pattern, calls `convex.mutation()`.
   - `window.CONVEX` stores the client instance.
   - Import ConvexHttpClient via ESM CDN: `import { ConvexHttpClient } from "https://esm.sh/convex@latest/browser"`.
   - Also import the `api` object for typed function references.

3. Create `app/login.html` — login page:

   - After successful login: call `redirectToRolePage()` from auth.js.
   - Include link to styles.css from shared/ for consistent styling.
   - Show company tagline "Menos leads, mas cierres" below login form.

4. Copy mockup HTML files to app/ directory — `app/ceo.html`, `app/vp-ventas.html`, `app/sdr.html`. These are copies from `mockups/` but with updated paths:
