**Workflow 1: saan-telegram-bot.json**

Create a complete n8n workflow JSON file for the Telegram bot. Structure per RESEARCH.md Pattern 4:

Nodes:
1. **Telegram Trigger** (n8n-nodes-base.telegramTrigger): Listen for messages and callback_query updates. Set allowedUpdates to ["message", "callback_query"]. Use Telegram API credential (user will configure).

2. **Switch: Update Type** (n8n-nodes-base.switch): Check if `{{ $json.callback_query }}` exists.
   - Output 0 (YES = callback_query): Route to callback handler
   - Output 1 (NO = message): Route to command router

3. **Switch: Command Router** (n8n-nodes-base.switch): Match on `{{ $json.message.text }}` — 4 outputs:
   - Output 0: starts with "/status"
   - Output 1: starts with "/help"
   - Output 2: starts with "/health"
   - Output 3 (fallback/extra): unknown command

4. **HTTP: Get All Agents** (n8n-nodes-base.httpRequest): POST to `{{ $vars.SAAN_CONVEX_SITE_URL }}/api/call` with header X-SAAN-Secret: `{{ $vars.SAAN_API_SECRET }}`, body: `{ "function": "agents:getAllAgentsState", "args": {} }`. Connected from /status output.

5. **Code: Format Status** (n8n-nodes-base.code): JavaScript that formats agent data as HTML per CONTEXT.md template. Use emojis per agent (from CONTEXT.md emoji table). Format each agent as: emoji + agentId + " — " + status. Include lastRun as relative time. Escape HTML entities in any data fields (replace & with &amp;, < with &lt;, > with &gt;).

6. **Telegram: Send Status** (n8n-nodes-base.telegram): Send message to `{{ $vars.TELEGRAM_CHAT_ID }}` with parse_mode HTML.

7. **Code: Format Help** (n8n-nodes-base.code): Static HTML help text listing: /status — Estado de todos los agentes, /help — Lista de comandos, /health — Salud de servicios. Include "Sisteco SAAN" as header.

8. **Telegram: Send Help** (n8n-nodes-base.telegram): Send to chat_id with HTML parse_mode.

9. **HTTP: Get Health** (n8n-nodes-base.httpRequest): POST to Convex /api/call, function "intelligence:getHealthSnapshot", args {}.

10. **Code: Format Health** (n8n-nodes-base.code): Format health snapshot as HTML. For each service, show status emoji (checkmark if latency < 300ms, warning if < 1000ms, X if null/high) + service name + latency.

11. **Telegram: Send Health** (n8n-nodes-base.telegram): Send to chat_id with HTML parse_mode.

12. **Code: Unknown Command** (n8n-nodes-base.code): Format "Comando no reconocido. Comandos disponibles:" + list of /status, /help, /health.

13. **Telegram: Send Unknown** (n8n-nodes-base.telegram): Send unknown command response.

14. **Code: Parse Callback** (n8n-nodes-base.code): Parse callback_data string. Expected format: "approve:TASK_ID", "reject:TASK_ID", "postpone:TASK_ID". Extract action and taskId. Add idempotency guard: store callback_query_id in static data and skip if seen before (prevents duplicate processing per Research pitfall 3).

15. **Switch: Callback Action** (n8n-nodes-base.switch): Route by action: approve -> update status "done", reject -> update status "cancelled", postpone -> update status "pending" (keeps it in queue).

16. **HTTP: Update Task (Approve)** (n8n-nodes-base.httpRequest): POST to Convex /api/call, function "agents:updateTaskStatus", args { taskId, status: "done", result: { approvedBy: "ceo", approvedAt: Date.now() } }.

17. **HTTP: Update Task (Reject)** (n8n-nodes-base.httpRequest): Same but status "cancelled".

18. **HTTP: Update Task (Postpone)** (n8n-nodes-base.httpRequest): Same but status "pending" (resets to pending).

19. **Telegram: Answer Callback** (n8n-nodes-base.telegram): Answer callback query to dismiss loading spinner. Operation: answerCallbackQuery. Text: action-specific toast ("Tarea aprobada", "Tarea rechazada", "Tarea pospuesta").

All nodes must have proper positions (spaced 220px horizontally, staggered vertically by branch). Include proper connections array. Tags: ["saan", "telegram", "fase-2"]. Settings: executionOrder "v1", saveManualExecutions true.

**Workflow 2: saan-telegram-consumer.json**

Create a cron-triggered workflow that drains the telegramQueue every 3 seconds.

Nodes:
1. **Schedule Trigger** (n8n-nodes-base.scheduleTrigger): Run every 3 seconds (use cron expression or interval setting). NOTE: n8n minimum interval is typically 1 minute for Schedule Trigger. Instead, use a **cron expression** `*/1 * * * *` (every minute) and inside the workflow, use a Loop node that runs 20 iterations with 3-second waits. OR simpler: use interval of 1 minute and process batch of up to 30 messages per run (Telegram allows 30/sec). Given the likely low volume, 1-minute interval is sufficient — process all pending in one batch.

   REVISED: Use Schedule Trigger with 1-minute interval. Process up to 30 pending messages per batch.

2. **HTTP: Get Pending** (n8n-nodes-base.httpRequest): POST to Convex /api/call, function "telegramQueue:getPending", args {}.

3. **IF: Has Messages** (n8n-nodes-base.if): Check if $json.data array has length > 0. If no, stop (no-op).

4. **Split In Batches** (n8n-nodes-base.splitInBatches): Process messages one at a time to respect Telegram rate limits.

5. **Telegram: Send Message** (n8n-nodes-base.telegram): Send message.content to $vars.TELEGRAM_CHAT_ID with parse_mode HTML. If message has inlineKeyboard, include it as reply_markup.

6. **HTTP: Mark Sent** (n8n-nodes-base.httpRequest): POST to Convex /api/call, function "telegramQueue:markSent", args { messageId: message._id }.

7. **Error Handler** (connected from Telegram Send error output): On send failure, call HTTP: Mark Failed with the message._id.

8. **HTTP: Mark Failed** (n8n-nodes-base.httpRequest): POST to Convex /api/call, function "telegramQueue:markFailed", args { messageId: message._id }.
