   - messageType: v.string() — "alert" | "report" | "task" | "system"
   - agentId: v.string()
   - priority: v.string() — "critical" | "high" | "normal" | "low"
   - content: v.string() — HTML formatted, ready to send
   - status: v.string() — "pending" | "consolidated" | "sent" | "failed"

   Add 3 indexes: `by_status_priority` on ["status", "priority"], `by_status_created` on ["status", "createdAt"], `by_consolidation` on ["consolidationWindow", "status"].

2. **Create `SAAN/convex/telegramQueue.ts`**: New file with these mutations/queries:
   - `enqueue` (mutation): Accepts messageType, agentId, priority, content, inlineKeyboard?. Sets status="pending", retryCount=0, createdAt=Date.now(). For CRITICAL priority, always status="pending". For WARNING/INFO, check if a consolidation window exists for same agentId within last 30 seconds — if yes, set consolidationWindow to that window ID and status="consolidated"; if no, create a new window ID (format: `win_${Date.now()}_${agentId}`), set consolidationWindow to it, status="pending".
   - `getPending` (query): Returns messages with status="pending" ordered by priority (CRITICAL first) then createdAt. Limit to 30 per batch (Telegram rate limit). Use the `by_status_priority` index to filter status="pending", then sort in code: CRITICAL > HIGH > NORMAL > LOW.
   - `getConsolidated` (query): Returns messages with status="consolidated" grouped by consolidationWindow. Returns array of { windowId, messages[] }.
   - `markSent` (mutation): Accepts messageId (v.id("telegramQueue")), sets status="sent", sentAt=Date.now().
   - `markFailed` (mutation): Accepts messageId (v.id("telegramQueue")), increments retryCount. If retryCount >= 3, set status="failed". Otherwise keep status="pending" (will be retried).
   - `getFailedCount` (query): Returns count of messages with status="failed" (for dashboard visibility per CONTEXT.md).

     f. If count < limit: insert new agentTask (same as existing createTask logic) and return the ID.
   - IMPORTANT: Do NOT modify the existing `createTask` — keep it as-is for backward compatibility. The new `createTaskWithBreaker` is used from n8n when circuit breaker protection is needed.
