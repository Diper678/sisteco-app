Crear `SAAN/convex/monitor.ts` con las siguientes funciones:

**Queries:**

1. `detectDownAgents` — Query que consulta `agentsState` y retorna agentes cuyo `lastRun` sea > 15 minutos atras (Date.now() - 15*60*1000). Excluir agentes con status "paused". Retorna array de { agentId, lastRun, minutesSinceLastRun }.

2. `getUptimeSummary24h` — Query que consulta `systemHealth` de las ultimas 24h para los 4 servicios core (vercel, convex_landing, convex_saan, n8n). Para cada servicio calcula:
   - totalChecks: cantidad de registros con metric="uptime"
   - successChecks: cantidad donde value=1
   - uptimePercent: (successChecks/totalChecks)*100 redondeado a 2 decimales
   - avgLatencyMs: promedio de registros con metric="latency_ms"
   - lastStatus: ultimo valor de metric="uptime" (1=up, 0=down)
   - incidents: cantidad de veces que value paso de 1 a 0 (transiciones a caida)
   Retorna Record<string, { totalChecks, successChecks, uptimePercent, avgLatencyMs, lastStatus, incidents }>

3. `getLastAlertTime` — Query que consulta `agentMemory` del agente "monitor" con memoryType="alert_sent", filtra por tag que contenga el nombre del servicio, y retorna el `createdAt` mas reciente. Args: { service: string }. Si no hay registros, retorna null. Esto es para idempotencia — evitar duplicar alertas tras reinicio de n8n.

**Mutations:**

4. `recordAlertSent` — Mutation que guarda en `agentMemory` un registro tipo "alert_sent" para el agente "monitor". Args: { service: string, severity: string, message: string }. Tags: [service, severity]. ExpiresAt: 24h (las alertas no necesitan persistir mas). Esto marca que ya se envio una alerta para ese servicio, evitando duplicados.

5. `checkServicesHealth` — Mutation que recibe un array de resultados de health check: `{ checks: Array<{ service: string, isUp: boolean, latencyMs: number }> }`. Para cada check:
   - Llama internamente a `ctx.db.insert("systemHealth", ...)` para registrar metric="uptime" con value=1 (up) o 0 (down) y unit="bool"
   - Llama internamente a `ctx.db.insert("systemHealth", ...)` para registrar metric="latency_ms" con el valor y unit="ms"
   - Retorna { recorded: number } con la cantidad de metricas guardadas

6. `updateMonitorState` — Mutation wrapper que llama a la logica de upsertAgentState para agentId="monitor". Args: { status: string, currentTask?: string, errorMessage?: string }. Calcula nextRun como Date.now() + 5*60*1000.

**IMPORTANTE:**
- Usar import { mutation, query, internalMutation } from "./_generated/server"
- Agregar "convex_saan" a los servicios monitoreados (actualmente getHealthSnapshot solo lista "vercel", "convex_landing", "n8n", etc.)
- Para getUptimeSummary24h, usar el index by_service_metric ya existente en systemHealth
- Para getLastAlertTime, usar el index by_agent_type ya existente en agentMemory

Crear `SAAN/n8n-workflows/saan-monitor-heartbeat.json` — un workflow n8n completo importable via UI.

**Estructura del workflow (nodos en orden):**

**Nodo 1: Schedule Trigger** (tipo: n8n-nodes-base.scheduleTrigger)
- Cron cada 5 minutos: `*/5 * * * *`

**Nodo 2: Define Services** (tipo: n8n-nodes-base.code)
- JavaScript que define los 4 servicios a verificar:
```javascript
const services = [
  { name: "vercel", url: "https://sisteco.cl", timeout: 10000 },
  { name: "convex_landing", url: "https://fine-cod-99.convex.site", timeout: 10000 },
  { name: "convex_saan", url: "{{ $vars.SAAN_CONVEX_SITE_URL }}", timeout: 10000 },
  { name: "n8n", url: "{{ $vars.N8N_BASE_URL }}/healthz", timeout: 10000 }
];
return services.map(s => ({ json: s }));
```
- NOTA: $vars.SAAN_CONVEX_SITE_URL y $vars.N8N_BASE_URL son variables de entorno de n8n que el usuario configura. Usar placeholders con $vars.

**Nodo 3: HTTP Health Check** (tipo: n8n-nodes-base.httpRequest, onEachItem)
- URL: `={{ $json.url }}`
- Method: GET
- Timeout: `={{ $json.timeout }}`
- Options: `{ "response": { "response": { "fullResponse": true } }, "timeout": {{ $json.timeout }} }`
- continueOnFail: true (si falla el request, no para el workflow)
- Captura statusCode y responseTime

**Nodo 4: Process Results** (tipo: n8n-nodes-base.code)
- Para cada item, construye objeto de resultado:
```javascript
const items = $input.all();
const results = items.map(item => {
  const service = item.json.name || item.json.url;
  const statusCode = item.json.statusCode || 0;
  const isUp = statusCode >= 200 && statusCode < 400;
  const latencyMs = item.json.responseTime || 0;
  return { json: { service, isUp, latencyMs, statusCode } };
});
return results;
```

**Nodo 5: Save to Convex** (tipo: n8n-nodes-base.httpRequest)
- Method: POST
- URL: `={{ $vars.SAAN_CONVEX_SITE_URL }}/api/call`
- Header: X-SAAN-Secret = `={{ $vars.SAAN_API_SECRET }}`
- Body JSON: `{ "function": "monitor:checkServicesHealth", "args": { "checks": [array de { service, isUp, latencyMs }] } }`
- Antes de enviar, el nodo Code previo debe agregar todos los resultados en un solo array (usar $input.all() y construir el array)

**Nodo 6: Check for Failures** (tipo: n8n-nodes-base.code)
- Filtra servicios con isUp=false
- Para cada servicio caido, consulta Convex si ya se envio alerta en las ultimas 2 horas:
  - Construye request a `/api/call` con function `monitor:getLastAlertTime` y args `{ service: nombre }`
- Retorna solo los servicios que necesitan alerta nueva (sin alerta reciente)

**Nodo 7: Check Down Agents** (tipo: n8n-nodes-base.httpRequest)
- POST a `{{ $vars.SAAN_CONVEX_SITE_URL }}/api/call`
- Body: `{ "function": "monitor:detectDownAgents", "args": {} }`
- Header: X-SAAN-Secret

**Nodo 8: Merge Alerts** (tipo: n8n-nodes-base.code)
- Combina servicios caidos (de nodo 6) + agentes caidos (de nodo 7)
- Para cada alerta, determina severidad:
  - Servicio caido = CRITICAL
  - Agente caido > 30 min = CRITICAL
  - Agente caido 15-30 min = WARNING
- Construye mensajes HTML con formato Telegram:

```html
<!-- Template CRITICAL -->
<b>🔍 Monitor Agent — ALERTA CRITICA</b>
━━━━━━━━━━━━━━━━━━
• Servicio: <b>{service}</b>
• Estado: ❌ CAIDO
• Latencia: {latencyMs}ms
• Status HTTP: {statusCode}

<b>Accion requerida:</b>
1. Verificar servicio manualmente
2. Revisar logs

<i>Severidad: 🔴 CRITICAL</i>
```

**Nodo 9: Enqueue Telegram Alerts** (tipo: n8n-nodes-base.httpRequest, onEachItem)
- Solo se ejecuta si hay alertas (usar IF node antes)
- POST a `{{ $vars.SAAN_CONVEX_SITE_URL }}/api/call`
- Body: `{ "function": "telegramQueue:enqueue", "args": { "messageType": "alert", "agentId": "monitor", "priority": "{severity}", "content": "{htmlMessage}" } }`
- Nota: usar la funcion de telegramQueue que Phase 2 crea para encolar mensajes

**Nodo 10: Record Alert Sent** (tipo: n8n-nodes-base.httpRequest, onEachItem)
- Para cada alerta enviada, marca en agentMemory:
- POST a `/api/call` con function `monitor:recordAlertSent`

**Nodo 11: Update Monitor State** (tipo: n8n-nodes-base.httpRequest)
- Siempre al final del workflow (exito o error):
- POST a `/api/call` con function `monitor:updateMonitorState`
- Si todo ok: `{ status: "idle", currentTask: null }`
- Si hubo error en el workflow: `{ status: "error", errorMessage: "..." }`

**Nodo 12: Purge Old Metrics** (tipo: n8n-nodes-base.httpRequest)
- Solo cada 12 ejecuciones (~1 vez por hora, usar modulo en Code node):
```javascript
const runCount = $workflow.runData?.length || 0;
if (runCount % 12 === 0) { /* ejecutar purge */ }
```
- POST a `/api/call` con function `intelligence:purgeOldMetrics`

**CRITICO para MON-08 (idempotencia tras reinicio n8n):**
- El workflow NO guarda estado en variables de n8n (se pierde con reinicio)
- Todo el estado vive en Convex (systemHealth, agentMemory)
- La anti-duplicacion de alertas se basa en `getLastAlertTime` — si ya hay alerta para ese servicio en las ultimas 2 horas, no enviar otra
- El Schedule Trigger de n8n retoma automaticamente tras reinicio (es cron-based, no interval-based)
- Usar `continueOnFail: true` en nodos HTTP para que un servicio inaccesible no bloquee el check de otros

**Conexiones del workflow:**
```
Schedule Trigger -> Define Services -> HTTP Health Check -> Process Results -> Save to Convex
Save to Convex -> Check for Failures -> [IF has failures] -> Enqueue Telegram Alerts -> Record Alert Sent
Save to Convex -> Check Down Agents -> Merge Alerts -> [IF has alerts] -> Enqueue Telegram Alerts
[Always] -> Update Monitor State -> [Conditional] -> Purge Old Metrics
```
