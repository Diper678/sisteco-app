**Estructura del workflow:**

**Nodo 1: Schedule Trigger** (tipo: n8n-nodes-base.scheduleTrigger)
- Cron: `0 8 * * *` con timezone `America/Santiago` (UTC-3 / UTC-4 segun horario verano)
- IMPORTANTE: n8n soporta timezone en Schedule Trigger — usar campo `timezone: "America/Santiago"`

**Nodo 2: Fetch Uptime Summary** (tipo: n8n-nodes-base.httpRequest)
- POST a `{{ $vars.SAAN_CONVEX_SITE_URL }}/api/call`
- Header: X-SAAN-Secret = `{{ $vars.SAAN_API_SECRET }}`
- Body: `{ "function": "monitor:getUptimeSummary24h", "args": {} }`

**Nodo 3: Fetch Agents Status** (tipo: n8n-nodes-base.httpRequest)
- POST a `{{ $vars.SAAN_CONVEX_SITE_URL }}/api/call`
- Header: X-SAAN-Secret = `{{ $vars.SAAN_API_SECRET }}`
- Body: `{ "function": "monitor:getAgentsStatusSummary", "args": {} }`

**NOTA:** Nodos 2 y 3 pueden ejecutarse en paralelo usando un SplitInBatches o simplemente secuencial (n8n no tiene paralelismo nativo por rama simple).

**Nodo 4: Build Report HTML** (tipo: n8n-nodes-base.code)
- Combina datos de uptime y agentes en un mensaje HTML formateado para Telegram:

```javascript
const uptime = $('Fetch Uptime Summary').first().json.data;
const agents = $('Fetch Agents Status').first().json.data;
const now = new Date();
const dateStr = now.toLocaleDateString('es-CL', { weekday: 'long', year: 'numeric', month: 'long', day: 'numeric' });

// Determinar estado general
const allServicesUp = Object.values(uptime).every(s => s.lastStatus === 1);
const overallEmoji = allServicesUp ? '✅' : '⚠️';

let html = `<b>🔍 Monitor Agent — Reporte Diario</b>\n`;
html += `<i>${dateStr}</i>\n`;
html += `━━━━━━━━━━━━━━━━━━\n\n`;

// Seccion 1: Servicios
html += `<b>${overallEmoji} Servicios (ultimas 24h)</b>\n`;
for (const [service, data] of Object.entries(uptime)) {
  const icon = data.uptimePercent >= 99.5 ? '🟢' : data.uptimePercent >= 95 ? '🟡' : '🔴';
  html += `${icon} <b>${service}</b>: ${data.uptimePercent}% uptime`;
  html += ` · ${Math.round(data.avgLatencyMs)}ms avg`;
  if (data.incidents > 0) html += ` · ${data.incidents} incidentes`;
  html += `\n`;
}

// Seccion 2: Agentes
html += `\n<b>🤖 Agentes (${agents.healthyCount}/${agents.totalAgents} operativos)</b>\n`;
for (const agent of agents.agents) {
  const icon = agent.isHealthy ? '🟢' : '🔴';
  html += `${icon} <b>${agent.agentId}</b>: ${agent.status}`;
  if (agent.errorCount > 0) html += ` (${agent.errorCount} errores)`;
  html += `\n`;
}

// Seccion 3: Resumen ejecutivo
html += `\n<b>📊 Resumen</b>\n`;
const avgUptime = Object.values(uptime).reduce((sum, s) => sum + s.uptimePercent, 0) / Object.keys(uptime).length;
html += `• Uptime promedio: <b>${avgUptime.toFixed(1)}%</b>\n`;
const totalIncidents = Object.values(uptime).reduce((sum, s) => sum + s.incidents, 0);
html += `• Incidentes totales: <b>${totalIncidents}</b>\n`;
html += `• Agentes con error: <b>${agents.errorCount}</b>\n`;

html += `\n<i>Severidad: 🔵 INFO — Reporte automatico diario</i>`;

return [{ json: { content: html, priority: totalIncidents > 0 ? 'normal' : 'low' } }];
```

**Nodo 5: Enqueue Report to Telegram** (tipo: n8n-nodes-base.httpRequest)
- POST a `{{ $vars.SAAN_CONVEX_SITE_URL }}/api/call`
- Body: `{ "function": "telegramQueue:enqueue", "args": { "messageType": "report", "agentId": "monitor", "priority": "{{ $json.priority }}", "content": "{{ $json.content }}" } }`
- NOTA: El contenido HTML puede contener comillas — escapar correctamente en el JSON body

**Nodo 6: Save Report to Memory** (tipo: n8n-nodes-base.httpRequest)
- POST a `/api/call` con function `agents:saveMemory`
- Args: `{ "agentId": "monitor", "memoryType": "report", "content": JSON.stringify({ date: dateStr, avgUptime, totalIncidents, agentErrors }), "tags": ["daily_report"] }`
- expiresAt: Date.now() + 90*24*60*60*1000 (90 dias — retencion de reports)

**Nodo 7: Update Monitor State** (tipo: n8n-nodes-base.httpRequest)
- POST a `/api/call` con function `monitor:updateMonitorState`
- Args: `{ "status": "idle", "currentTask": null }`

**Conexiones:**
```
Schedule Trigger -> Fetch Uptime Summary -> Fetch Agents Status -> Build Report HTML -> Enqueue Report to Telegram -> Save Report to Memory -> Update Monitor State
```

**Settings:**
- executionOrder: "v1"
- tags: ["saan", "monitor", "fase-3", "daily-report"]

**Idempotencia (MON-08):**
- El cron de n8n es declarativo (8:00 AM Santiago) — si n8n se reinicia a las 7:59 AM, el cron aun se dispara a las 8:00 AM
- Si n8n estuvo caido a las 8:00 AM y se reinicia a las 9:00 AM, n8n NO re-ejecuta crons perdidos por defecto. Esto es aceptable — el reporte se pierde ese dia pero las alertas criticas son en tiempo real via heartbeat
- El Save Report to Memory permite que el CEO vea desde dashboard si falto un reporte
