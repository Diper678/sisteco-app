Crear `SAAN/convex/leadsSkills.ts` con funciones que operan sobre la tabla `skillsRegistry` existente (NO crear tabla nueva):

1. **registerLeadsSkill** (mutation): Registra o actualiza una skill del Leads Agent en skillsRegistry.
Args: skillId, skillName, description, skillType, config (JSON con parametros de la skill como queries, rules, etc.)
Si ya existe (by skillId), actualiza. Si no, crea con agentOwner="leads", usageCount=0, isActive=true.

2. **recordSkillUsage** (mutation): Registra que una skill fue usada.
Args: skillId, result (JSON con metricas: { leadsGenerated, leadsUpdated, costUsd, errorsCount, duration_ms })
Actualiza usageCount +1, lastUsed=Date.now().
Tambien guarda en agentMemory un registro detallado:
```typescript
await ctx.db.insert("agentMemory", {
  agentId: "leads",
  memoryType: "skill_usage",
  content: JSON.stringify({ skillId, ...result, timestamp: Date.now() }),
  tags: ["skill_performance", skillId],
  createdAt: Date.now(),
});
```

3. **getSkillPerformance** (query): Retorna rendimiento agregado de todas las skills del Leads Agent.
Lee de skillsRegistry (where agentOwner="leads") + ultimas 50 memorias tipo "skill_usage".
Retorna por cada skill:
```typescript
{
  skillId: string,
  name: string,
  totalUses: number,
  lastUsed: number | null,
  isActive: boolean,
  // Metricas agregadas de las ultimas 50 memorias
  totalLeadsGenerated: number,
  totalCostUsd: number,
  avgLeadsPerRun: number,
  costPerLead: number,
  errorRate: number,
  // Config actual
  config: any,
}
```

4. **updateSkillConfig** (mutation): Actualiza la config de una skill (por ejemplo, cambiar queries de busqueda o extract_rules).
Args: skillId, newConfig (partial merge con config existente), reason (string — por que se cambio).
Guarda el cambio en agentMemory como decision:
```typescript
await ctx.db.insert("agentMemory", {
  agentId: "leads",
  memoryType: "decision",
  content: JSON.stringify({ type: "skill_config_update", skillId, reason, oldConfig: skill.config, newConfig: merged, timestamp: Date.now() }),
  tags: ["metacognition", "skill_improvement", skillId],
  createdAt: Date.now(),
});
```

5. **createNewSkill** (mutation): El agente propone y registra una skill completamente nueva.
Args: skillName, description, skillType, config, parameters, reasoning (por que la creo).
Crea en skillsRegistry + guarda en agentMemory como "skill_detected".
Crea tarea para CEO (agents:createTask) para revision:
```json
{ "fromAgent": "leads", "toAgent": "human", "taskType": "new_skill_proposal", "priority": "normal", "payload": { "skillName": ..., "reasoning": ..., "config": ... } }
```

6. **deactivateSkill** (mutation): Desactiva una skill que no esta rindiendo.
Args: skillId, reason.
Patch isActive=false. Guarda decision en agentMemory.

7. **initializeLeadsSkills** (mutation): Registra las 6 skills iniciales del Leads Agent (llamar una vez al deployar).
Registra: leads-discover-firecrawl, leads-discover-phantombuster, leads-discover-scrapingbee, leads-enrich-firecrawl, leads-score-gemini, leads-sdr-outreach.
Cada una con su config inicial (queries, APIs, rate limits, etc.).

**Nodo 9 — Apply Automatic Improvements:**
Code node que decide que mejoras aplicar automaticamente vs. cuales requieren aprobacion del CEO:

```javascript
const analysis = $json;

// Mejoras automaticas (bajo riesgo):
// - Cambios de queries de busqueda
// - Ajustes de rate limits
// - Activar/desactivar una skill

// Requieren aprobacion CEO:
// - Crear skill nueva
// - Cambiar modelo de AI
// - Incrementar presupuesto

const autoApply = [];
const needsApproval = [];

for (const imp of analysis.improvements || []) {
  if (imp.change_type === 'config_update' && !imp.proposed_value?.includes('model')) {
    autoApply.push(imp);
  } else {
    needsApproval.push(imp);
  }
}

return {
  json: {
    autoApply,
    needsApproval,
    newSkills: analysis.new_skill_proposals || [],
    deactivations: analysis.deactivation_proposals || [],
    summary: analysis.weekly_summary,
    analysis: analysis.analysis,
  }
};
```
