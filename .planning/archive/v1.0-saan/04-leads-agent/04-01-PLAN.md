```typescript
icpProfiles: defineTable({
  name: v.string(),                    // "Sisteco Principal", "Enterprise", "SMB"
  isActive: v.boolean(),               // Solo 1 perfil activo a la vez para scoring

  // Criterios del ICP
  industries: v.array(v.string()),     // ["saas", "fintech", "servicios_profesionales", "manufactura", "logistica"]
  minEmployees: v.number(),            // 50
  maxEmployees: v.optional(v.number()), // 500
  locations: v.array(v.string()),      // ["Santiago", "Chile"]
  companyTypes: v.array(v.string()),   // ["b2b"]

  // Senales de compra
  buyingSignals: v.array(v.string()),  // ["necesita_crm", "equipo_ventas_3+", "sin_automatizacion", "crecimiento_rapido"]
  techStackPositive: v.array(v.string()),  // ["hubspot", "salesforce", "pipedrive"] — usan CRM = saben de ventas
  techStackNegative: v.array(v.string()), // ["competitor_x"] — ya usan competencia

  // Pesos de scoring (suman 100)
  weights: v.object({
    industryFit: v.number(),           // 30 — Industria y modelo B2B alineado
    companySize: v.number(),           // 25 — Tamano de empresa adecuado
    buyingIntent: v.number(),          // 20 — Senales de necesidad
    contactQuality: v.number(),        // 15 — Datos de contacto disponibles
    techFit: v.number(),               // 10 — Stack tecnologico compatible
  }),

  // Decision makers objetivo
  targetRoles: v.array(v.string()),    // ["VP Ventas", "Director Comercial", "Gerente de Ventas", "CEO", "CRO"]

  // Metadata
  createdAt: v.number(),
  updatedAt: v.number(),
  createdBy: v.string(),               // "ceo" | "leads_agent"
})
  .index("by_active", ["isActive"])
  .index("by_name", ["name"]),
```

**Tabla 2: leads** (expandida para multi-fuente + SDR)
```typescript
leads: defineTable({
  // Identificacion
  empresa: v.string(),
  contacto: v.optional(v.string()),
  cargo: v.optional(v.string()),        // NUEVO: cargo del contacto (decision maker)
  email: v.optional(v.string()),
  telefono: v.optional(v.string()),
  linkedinUrl: v.optional(v.string()),
  websiteUrl: v.optional(v.string()),

  // Clasificacion
  industria: v.optional(v.string()),
  tamano: v.optional(v.string()),       // "50-100", "100-500", "500+"
  ubicacion: v.optional(v.string()),
  companyType: v.optional(v.string()),  // NUEVO: "b2b", "b2c", "b2b2c"

  // Scoring
  score: v.number(),                    // 0-100
  scoreCategory: v.string(),            // "HOT" | "WARM" | "NURTURE" | "SKIP"
  scoreReasoning: v.optional(v.string()),
  scoreVersion: v.optional(v.number()), // NUEVO: version del ICP usado para scoring
  scoredAt: v.optional(v.number()),     // NUEVO: cuando se hizo el scoring

  // Enriquecimiento
  enrichedData: v.optional(v.any()),    // { descripcion, productos, stack, empleados, etc. }
  enrichedAt: v.optional(v.number()),

  // Multi-fuente tracking
  source: v.string(),                   // "firecrawl_search" | "phantombuster_linkedin" | "scrapingbee_directory" | "manual"
  sourceUrl: v.optional(v.string()),
  sourceDetails: v.optional(v.any()),   // NUEVO: metadata especifica de la fuente (phantom container ID, etc.)
  estimatedCostUsd: v.optional(v.number()), // NUEVO: costo de adquisicion de este lead (credits usados)

  // Pipeline SDR
  status: v.string(),                   // "new" | "enriched" | "scored" | "outreach_queued" | "contacted" | "replied" | "meeting_booked" | "converted" | "rejected" | "nurturing"
  outreachStage: v.optional(v.string()), // NUEVO: "none" | "email_1" | "linkedin_connect" | "email_2" | "phone_call" | "email_3"
  outreachStartedAt: v.optional(v.number()),
  lastContactedAt: v.optional(v.number()),
  nextFollowUpAt: v.optional(v.number()),  // NUEVO: cuando hacer siguiente contacto
  outreachNotes: v.optional(v.string()),   // NUEVO: notas del agente sobre outreach

  // Skill tracking
  discoveredBySkill: v.optional(v.string()), // NUEVO: skillId que descubrio este lead
  enrichedBySkill: v.optional(v.string()),   // NUEVO: skillId que enriquecio
  scoredBySkill: v.optional(v.string()),     // NUEVO: skillId que hizo scoring

  // Timestamps
  discoveredAt: v.number(),
  lastUpdatedAt: v.number(),
})
  .index("by_email", ["email"])
  .index("by_empresa", ["empresa"])
  .index("by_status", ["status"])
  .index("by_score_category", ["scoreCategory"])
  .index("by_score", ["score"])
  .index("by_discovered", ["discoveredAt"])
  .index("by_source", ["source"])
  .index("by_outreach_stage", ["outreachStage"])
  .index("by_next_followup", ["nextFollowUpAt"]),
```

Crear `SAAN/convex/leads.ts` con las siguientes funciones:

1. **upsertLead** (mutation): Recibe datos del lead. Busca primero por email (si tiene), luego por empresa. Si encuentra, hace patch con datos nuevos (merge). Si no, inserta con defaults: `status="new"`, `score=0`, `scoreCategory="SKIP"`, `discoveredAt=Date.now()`. Siempre actualiza `lastUpdatedAt`. Si viene `discoveredBySkill`, lo guarda.

2. **batchUpsertLeads** (mutation): Recibe array de leads + `sourceSkillId` opcional. Para cada uno llama logica de upsertLead. Retorna `{ inserted, updated, total, estimatedCostUsd }`. Max 50 por batch. Si viene `costPerLead`, calcula costo total.

3. **getLeadByEmail** (query): Busca por indice `by_email`. Retorna el primero o null.

4. **getLeadByCompany** (query): Busca por indice `by_empresa`. Retorna el primero o null.

5. **getLeadsByStatus** (query): Filtra por status. Acepta limit (default 50).

6. **getLeadsByScore** (query): Acepta `minScore`. Filtra score >= minScore. Ordena desc. Limit (default 50).

7. **updateLeadStatus** (mutation): Recibe leadId y status. Patch con nuevo status y lastUpdatedAt.

8. **updateLeadScore** (mutation): Recibe leadId, score, scoreCategory, scoreReasoning, scoreVersion, scoredBySkill. Patch todos + `scoredAt=Date.now()` + `lastUpdatedAt`. Si score >= 80, tambien cambia status a "scored".

9. **enrichLead** (mutation): Recibe leadId, enrichedData, enrichedBySkill. Patch enrichedData, status="enriched", enrichedAt, enrichedBySkill. Si enrichedData contiene industria_detectada o tamano_detectado, actualiza campos principales.

10. **getLeadsToEnrich** (query): Leads con status="new", limit 20.

11. **getLeadsToScore** (query): Leads con status="enriched", limit 20.

12. **updateOutreachStatus** (mutation): Recibe leadId, outreachStage, outreachNotes. Actualiza outreachStage, lastContactedAt=Date.now(), calcula nextFollowUpAt (3 dias despues). Si es primer outreach, status="contacted", outreachStartedAt=Date.now().

13. **getLeadsForOutreach** (query): Leads con scoreCategory IN ["HOT", "WARM"] y status="scored". Limit 20. Estos son los que estan listos para el SDR.

14. **getLeadsStats** (query): Sin args. Retorna:

```typescript
  total: N,
  totalEstimatedCostUsd: N
}
```

15. **getLeadsBySource** (query): Filtra por source. Acepta limit (default 50). Usa indice `by_source`.
